# Four-workflow integration evidence

Run `bun run evaluate:workflows`. The [captured artifact](workflows-v1.json) is reproducible deterministic evidence from
`packages/evaluation/src/workflows.ts` and its public behavior tests. It extends the approved temporary SQLite/shared
runtime/actual adapter seams without changing the pinned baseline fixtures or legacy comparator. No private session,
Collection, provider account or live model is used.

The synthetic Heroic Feast style demonstration models repeat creature sacrifice → conditional access → death rewards
→ life loss. Names and rules are deliberately synthetic. They demonstrate the adopted plan-first methodology, not a
transcript reconstruction, legal public-card deck or certified strategy. The Commander skill's compact Meren example
contains separately sourced public card facts; both Format owners contain executable exact-calculator requests.

| Workflow | Observable evidence |
| --- | --- |
| Discovery | Catalogue-valid synthetic seed, paged tag search plus independent text search, five inspected examples, a tag-only mismatch rejected, scoped owned evidence retrieved without repeated provider text, no candidate persisted. One direction qualifies under stated fixture assumptions; no quota or exhaustive-search claim. |
| Construction | Six assessed options with meaningful role contributions and conditions, desired gaps, empty selection saved, connections reopened, original reasoning/options recovered through bounded JSON, then 60 selected copies assembled without implicit checks. |
| Tuning | One accepted access swap loses secondary sacrifice density (eight to seven); unaccepted compensation contributes nothing. Actual aggregate is saved with its caveat, viable options retained. |
| Assembly | Explicit saved legality/evaluation and whole-policy Availability; 60 selected copies allocated jointly, bounded Pull List recovered, pool-only basic alternative excluded from Portable Decklist. A transient Mainboard/Sideboard overlap needs two copies where only one exists and reports one Missing-owned copy. |

Actual Pi Worker, Pi fallback and OpenCode tool execution return identical complete selected-view envelopes. The
capability audit compares normal registries and OpenCode permissions, checks retired retrieval/readiness/save names
are absent, verifies legacy is disabled by default, reads all eight canonical skills through Pi's constrained `read`,
and resolves OpenCode's native-skill links to those same files. It audits available skill sources and routing; it does
not invoke a live native model or prove that a model follows instructions.

Calculator results use exact uniform sampling without replacement: 12 qualifying copies in a 99-card population,
nine sampled, at least one: 0.703692876224591; four in 60, seven sampled: 0.3994996257446656. A chosen 60% target in the
latter sample requires seven compatible qualifying copies. Assume no mulligans, search, extra draws or known cards;
exclude commanders and Sideboards from the library population. These are access events, not mana, casting or win rates.

The scripted decisions are independently reviewable fixture assumptions. They do not evaluate live-model shortlist
quality, source completeness, opportunity recall, authorization dialogue, gameplay, actual human acceptance or real-session
Pi parity. Review those separately with the [manual corpus](../testing/deck-building-workflow-scenarios.md). No LLM judge,
golden deck, strategic score, provider/model CI call or account acceptance claim is introduced. Timing comparisons remain
with `evaluate:performance`; this correctness artifact supplies no latency claim.

For separately consented matched live sessions, use the [real-session parity protocol](real-session-parity.md) and
[result template](real-session-parity-results-template.md). Fixture preparation and deterministic integration evidence
do not establish model/account acceptance.
