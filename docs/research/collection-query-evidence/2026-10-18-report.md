# Collection retrieval evidence

Reproduce with `bun run evaluate:collection-query`. The JSON beside this report records one cold run, one unmeasured
warmup and five warm samples per workflow, using the existing `synthetic-workflows-v1` populations and exact binder
scope. Each isolated migrated SQLite Collection becomes an authoritative successful snapshot. An injected four-card
provider and three-result application pages exercise refetch-and-anchor recovery. No private data, live Scryfall,
model session or production database is used.

These are whole compact UTF-8 envelopes, including both self-contained cursors, repeated fixed policy inputs and one
inspectable Collection context. The first page returns three results; legacy totals return every result at once. Full
traversal bytes make the repeated metadata cost visible. This is not a payload-reduction claim: new evidence preserves
complete rules text, exact compatible/eligible quantities, actual owned Printing joins, confirmed permission and complete
selected rows. The frozen legacy result lacks that permission proof and clips long Oracle text. Construction/assembly
legacy Pi previews lose all 26 complete records without recovery; the new Worker and fallback return complete pages.
The baseline artifact is [pre-migration-v1.json](../../evaluation/pre-migration-v1.json).

Every traversal has zero missing, unexpected or duplicate identities. Expected row IDs, Printing IDs, quantities and
finish are checked independently against the fixture's source rows, and all selected allowed rows are present. The first
application, OpenCode serializer, Pi fallback and actual Pi Worker envelopes are exactly equal. All selected 1,300-character
Oracle text is retained. Provider traversal calls include expected mid-page refetches; adapter first-page calls are recorded
separately. The runner does not cache results. Synthetic admission offsets and measured local cold/warm stage durations
are in the JSON; no live throughput inference is justified. Token counts are explicitly estimated as ceil(UTF-8 bytes / 4).

Public-runtime/real-SQLite and actual adapter regressions additionally establish:

- A representative provider Printing differing from the owned Printing never supplies owned-version facts.
- Identity/explicit Printing scope, exact type/name or UUID locations, all conjuncts on the same row, and unknown strict
  metadata produce exact compatible ownership, eligible/uncertain quantities and matching-only copies.
- Unconfirmed policy, no Collection, imported empty, legacy reimport requirement and permitted Committed borrowing stay
  distinct. No copy list is a diagnostic all-rows dump or a reservation/allocation claim.
- Scope filtering fills across nonmatching/empty work and preserves raw provider anchors. Zero-first and selector changes
  preserve ordinary recovery. A 140-row selected copy list is indivisible; oversize rejection stays before its card, and
  changed copy selection recovers all 140 rows without a missing/duplicate row. Unfinished date/deadline work emits no
  partial number.
- Concurrent Collection replacement discards dependent in-flight results. Candidate policy changes and successful
  same-tick reference replacement invalidate cursors; failed/unrelated imports and candidate label edits do not.
- Actual OpenCode independent schema registries, Pi Worker and fallback retain closed selectors, complete payloads beyond
  16,000 characters, structured errors and cancellation without invented progress.

Search/lookup evidence remains per-card retrieval evidence. It cannot establish sufficient joint allocation for a final
deck or all-owned-Printing coverage from collapsed provider results. The final Availability service owns those claims.
